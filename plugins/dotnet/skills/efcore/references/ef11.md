# EF Core 11 features

EF Core 11 is GA (11.0.0, 2026-11-10), STS, and requires .NET 11. Items marked
**experimental** must not be introduced unless the user asks. Main source:
[What's new in EF Core 11](https://learn.microsoft.com/en-us/ef/core/what-is-new/ef-core-11.0/whatsnew)
(the page may still say "in development": that wording is stale).

## Complex types

- **Complex types/JSON on TPT and TPC hierarchies**: previously unsupported. GA.
- **Complex types in Cosmos DB**: nested JSON objects/arrays, with query, insert and update. Preferred over owned types in Cosmos. GA.
- **Lambda chaining for configuration**: `modelBuilder.Entity<E>().Property(e => e.Details.Description).HasMaxLength(500);` GA.
- **Keys and indexes on complex-type properties**: `HasKey(c => c.CustomerId.Value)`, `HasIndex(c => c.Address.PostalCode)`, or by name `HasIndex("Address.PostalCode")`. JSON paths: `HasIndex("Items[].Sku")` (needs JSON index support, for example SQL Server 2025). GA.
- **Stabilization**: many fixes (nested comparison, ExecuteUpdate nested assignment, TPH nullability, ReloadAsync with null optional complex). This is the stated goal: "unblock using complex types as an alternative to owned".

## LINQ and SQL

- **`FullJoin` (.NET 11 operator)**: translates to `FULL JOIN`. GA. Relational only.

```csharp
var r = await ctx.Customers.FullJoin(ctx.Orders, c => c.Id, o => o.CustomerId,
    (c, o) => new { Customer = c, Order = o }).ToListAsync();
```

- **`MaxBy`/`MinBy` (+ `MaxByAsync`/`MinByAsync`)**: translate to `ORDER BY ... DESC` + `TOP(1)`. GA.

```csharp
// Old
var b = await ctx.Blogs.OrderByDescending(b => b.Posts.Count()).FirstOrDefaultAsync();
// New
var b = await ctx.Blogs.MaxByAsync(b => b.Posts.Count());
```

- **Better SQL for to-one includes** (perf): split queries no longer join reference navigations in collection queries, and redundant reference keys are dropped from ORDER BY. Microsoft benchmarks show about **29%** (split) and **22%** (single) improvement. Automatic.
- **GroupBy improvements**: navigation and joins over per-group top results; aggregates over reference navigations use joins instead of correlated subqueries; DTO/anonymous left-join materialization fixed.
- **No-op CAST stripping** (perf): removes `CAST(col AS same_type)`, mostly from value converters, so indexes become usable again. Automatic.
- **`EF.Functions.JsonPathExists(json, "$.path")`**: SQL Server `JSON_PATH_EXISTS` (SQL Server 2022+). Works on string columns, complex/owned JSON.
- **Analyzer**: warns on `ToAsyncEnumerable` instead of `AsAsyncEnumerable` on EF queries.

## SQL Server

- **`VECTOR_SEARCH()` + vector indexes: EXPERIMENTAL** (both SQL Server-side and EF API "subject to change"). SQL Server 2025.

```csharp
modelBuilder.Entity<Blog>().HasVectorIndex(b => b.Embedding, "cosine"); // CREATE VECTOR INDEX
var hits = await ctx.Blogs
    .VectorSearch(b => b.Embedding, queryVector, "cosine")   // VectorSearchResult<Blog>
    .OrderBy(r => r.Distance).Take(5)
    .WithApproximate()   // ANN via index; must come after Take(); omit for exact kNN
    .ToListAsync();      // r.Value = entity, r.Distance
```

- **Vector properties not loaded by default** (GA, breaking): `SqlVector<T>` is excluded from entity SELECTs and is `null` on materialized entities. It is still usable in WHERE/ORDER BY. Microsoft benchmarks show about 9x (local) and 22x (remote Azure SQL) speedups. Read vectors via explicit projection `Select(b => new { b.Id, b.Embedding })`. The breaking-changes page says a public opt-back-in mechanism "will be introduced later"; the GitHub issue (#37279, closed for 11.0.0) shows only internal `IsAutoLoaded` metadata. **No verified public opt-in API.**
- **Full-text search**: `modelBuilder.HasFullTextCatalog("ftCatalog")` + `HasFullTextIndex(b => b.FullName).UseKeyIndex("PK_Blogs").UseCatalog("ftCatalog")`, created by migrations. **Table-valued functions** `FreeTextTable(...)` / `ContainsTable(...)` return `FullTextSearchResult<T>` with `.Value` and `.Rank`. GA.
- **Hybrid search on SQL Server**: `FreeTextTable` + `VectorSearch` + `FullJoin` + manual RRF score (documented pattern; inherits experimental status from `VectorSearch`).
- **`JSON_CONTAINS` translation**: `b.Tags.Contains("x")` over JSON primitive collections uses `JSON_CONTAINS` (can use JSON indexes) when compat level is 170, and at least one side is known non-null. Otherwise it falls back to OPENJSON. Also explicit `EF.Functions.JsonContains(json, value, path?, mode?)`.
- **JSON indexes**: `HasIndex("Contact.Address.City")` on JSON-mapped complex types generates `CREATE JSON INDEX ... FOR (N'$.Address.City')`. SQL Server 2025.
- **Temporal period columns as CLR properties**: `b.IsTemporal(t => { t.HasPeriodStart(e => e.PeriodStart); t.HasPeriodEnd(e => e.PeriodEnd); })`. You no longer need `EF.Property<DateTime>(e, "PeriodStart")`.
- **DateTimeOffset translations**: `.DateTime`, `.UtcDateTime`, `.LocalDateTime`, `.Offset.TotalMinutes`, `ToOffset()` (SWITCHOFFSET), `new DateTimeOffset(dt[, offset])` (TODATETIMEOFFSET). `EF.Functions.DateTrunc()` (DATETRUNC).
- **Default compatibility level is now 160** (SQL Server 2022): LEAST/GREATEST are used by default (breaking for SQL Server 2019 and older).

## SQLite

- Ordered `string.Join`/`string.Concat` over groups uses `group_concat(... ORDER BY ...)` (needs SQLite 3.44+). Previously this was client eval.
- `Microsoft.Data.Sqlite` can bind `UInt128` (stored as 39-digit text). Reading it is not yet supported.

## Cosmos DB

- Complex types (above).
- **Indexing policy**: `HasAutomaticIndexing().Except("/path/?")`, composite/single/vector/full-text indexes via `HasIndex` (including complex paths `o.Items.Select(i => i.Sku)`).
- **Transactional batches by default**: `AutoTransactionBehavior.Auto` groups operations per container and partition. `Never` restores the old behavior. `Always` throws if the operations don't fit in one batch. Perf plus best-effort atomicity.
- **Bulk execution**: `UseCosmos(..., o => o.BulkExecutionEnabled())`.
- **Session tokens**: `o.SessionTokenManagementMode(SessionTokenManagementMode.SemiAutomatic)`, `Database.GetSessionToken()`/`UseSessionToken()` (read-your-writes across instances).
- **System.Text.Json serializer** (perf): Newtonsoft.Json removed, along with `__jObject` (breaking).
- Projections that evaluate to `undefined` now always throw. Use `EF.Functions.IsDefined`/`CoalesceUndefined`.

## Migrations and tooling

- **`ExcludeForeignKeyFromMigrations()`**: keeps the relationship in the model and skips the DB FK constraint (the index is still created).
- **Model snapshot records the latest migration ID**: divergent branches now produce a merge conflict.
- **`dotnet ef database update <Name> --add`**: scaffold + Roslyn-compile + apply in one step (Aspire/containers). PMC: `Update-Database -Migration X -Add`.
- `migrations remove --connection/--offline/--force`, `database drop --connection`.
- **`.config/dotnet-ef.json`**: default `project`, `startupProject`, `context`, `framework`, and so on.
- PMC `-NoBuild` for `Add-Migration`/`Update-Database`.
- `--context "*"` wildcard for `migrations list/script`, `database update/drop`.
- Tool logs go to stderr; stdout carries only output (for example a clean SQL script).
