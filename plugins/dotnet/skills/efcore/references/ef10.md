# EF Core 10 features (and the EF Core 7-9 baseline)

EF Core 10 is GA and LTS (supported until 2028-11-10) and requires .NET 10.
Every item below is GA unless marked otherwise. Main sources:
[What's new in EF Core 10](https://learn.microsoft.com/en-us/ef/core/what-is-new/ef-core-10.0/whatsnew),
[complex types](https://learn.microsoft.com/en-us/ef/core/modeling/complex-types),
[query filters](https://learn.microsoft.com/en-us/ef/core/querying/filters).

## Baseline: EF Core 7/8/9 features that are still the modern way (one line each)

- **ExecuteUpdate/ExecuteDelete (EF7)**: set-based UPDATE/DELETE without loading entities. Bypasses the change tracker, so no SaveChanges is needed and tracked entities are not updated.
- **Complex types (EF8)**: value objects with no key, via `[ComplexType]` or `ComplexProperty`. Not discovered by convention. EF10 made them the preferred replacement for owned types.
- **Primitive collections (EF8)**: `string[]`/`List<int>` properties stored as JSON (arrays on PostgreSQL) and queryable with LINQ. EF9 added read-only collections.
- **Parameterized collections in queries (EF8)**: `ids.Contains(x.Id)` is translated server-side. EF9 added `EF.Constant`/`EF.Parameter`. The EF10 default changed, see below.
- **JSON columns (EF7/8)**: `ToJson()` on owned types. In EF10+, use `ComplexProperty(...).ToJson()` / `ComplexCollection(...).ToJson()` instead.
- **`SqlQuery<T>` for unmapped types (EF8)**: raw SQL to arbitrary DTOs.
- **HierarchyId (EF8)**, **DateOnly/TimeOnly on SQL Server (EF8)**.
- **`UseSeeding`/`UseAsyncSeeding` (EF9)**: the recommended seeding mechanism. Runs on `EnsureCreated`, `Migrate` and `dotnet ef database update`, under the migration lock. Must be idempotent. `HasData` is now called "model managed data" and is only for static, deterministic data. Source: <https://learn.microsoft.com/en-us/ef/core/modeling/data-seeding>
- **`PendingModelChangesWarning` throws (EF9)**: `Migrate()` throws if the model differs from the last migration. A common cause is non-deterministic `HasData` (`DateTime.Now`, `Guid.NewGuid()`).
- **Migration locking (EF9)**: protects against concurrent `MigrateAsync()`. Applying migrations at deploy time (bundles or scripts) is still preferred.
- **Complex types in GroupBy/ExecuteUpdate (EF9)**: you can assign a whole complex value in `SetProperty`.
- **`UseAzureSql`/`UseAzureSynapse` (EF9)**: use these instead of `UseSqlServer` for Azure targets. `UseAzureSql` enables Azure-specific SQL, and in EF10 the native `json` type by default.
- **Auto-compiled models plus MSBuild integration (EF9)**: `Microsoft.EntityFrameworkCore.Tasks`.
- **NativeAOT / precompiled queries (EF9)**: **still labeled experimental** in Learn docs. No dynamic LINQ, no query syntax. EF11 removed `EFOptimizeContext` (see breaking changes).
- **Cosmos: sync I/O throws (EF9)**: sync I/O was removed entirely in EF11.
- **`ToHashSetAsync` (EF9)**.

## EF Core 10 features (all GA in 10.0.0 unless noted)

### 1. `LeftJoin` / `RightJoin` LINQ operators

- **Version/status**: EF10, GA. Requires .NET 10 (`System.Linq.Queryable.LeftJoin`/`RightJoin`).
- **Providers**: all relational providers (translated to LEFT JOIN / RIGHT JOIN).
- **What**: first-class left/right outer join, replacing the `GroupJoin` + `SelectMany` + `DefaultIfEmpty` pattern. C# query syntax does not support it, so use method syntax.

```csharp
// Old
var q = from s in ctx.Students
        join d in ctx.Departments on s.DepartmentID equals d.ID into g
        from d in g.DefaultIfEmpty()
        select new { s.FirstName, Department = d.Name ?? "[NONE]" };
// New (EF10)
var q = ctx.Students.LeftJoin(ctx.Departments,
    s => s.DepartmentID, d => d.ID,
    (s, d) => new { s.FirstName, Department = d.Name ?? "[NONE]" });
```

- **Use when**: you are joining unrelated sets or have no navigation. **Prefer** navigations + `Include`/projection when a relationship exists.
- **Note**: the inner element can be null. Handle it with `?.`/`??` in the projection. EF11 adds `FullJoin` (see below).
- **Source**: whatsnew EF10, "Support for the .NET 10 LeftJoin and RightJoin operators".

### 2. Named query filters

- **Version/status**: EF10, GA (contributed by @bittola). The Learn filters page still has a stale "(in preview)" note.
- **Providers**: all.
- **What**: multiple filters per entity type, each named. `IgnoreQueryFilters(["Name"])` disables only the listed filters. Calling unnamed `HasQueryFilter` twice still overwrites the previous filter.

```csharp
// Old: one combined filter, all-or-nothing
modelBuilder.Entity<Blog>().HasQueryFilter(b => !b.IsDeleted && b.TenantId == tenantId);
ctx.Blogs.IgnoreQueryFilters(); // also drops the tenant filter (security risk)

// New (EF10)
modelBuilder.Entity<Blog>()
    .HasQueryFilter("SoftDelete", b => !b.IsDeleted)
    .HasQueryFilter("Tenant", b => b.TenantId == tenantId);
ctx.Blogs.IgnoreQueryFilters(["SoftDelete"]); // tenant filter still applied
```

- **Use when**: soft delete + multitenancy. **Security**: lets you show soft-deleted rows without disabling tenant isolation. Use constants for filter names.
- **Caveats (unchanged)**: filters only on the root of an inheritance hierarchy. Required navigations to filtered entities cause INNER JOIN row loss. There is no cycle detection.
- **Source**: whatsnew EF10, <https://learn.microsoft.com/en-us/ef/core/querying/filters>

### 3. Complex types: optional, JSON, structs, collections (GA)

- **Version/status**: EF10, GA. EF11 adds more (see EF11 section).
- **Providers**: relational (SQL Server, SQLite, Npgsql 10 maps `ToJson()` to `jsonb`). Cosmos complex types arrive in EF11.
- **What**:
  - **Optional complex types**: declare `Address?`. The complex type needs at least one required property, or configure `b.HasDiscriminator()` (creates a required shadow property).
  - **JSON mapping**: `ComplexProperty(x => x.P, b => b.ToJson())`.
  - **Complex collections**: `ComplexCollection(x => x.Items, b => b.ToJson())`. On relational providers these must be JSON.
  - **Structs**: `struct`/`record struct` complex types are supported. Collections of structs are not.
  - **Value semantics**: assigning `a.Billing = a.Shipping` copies values, and `==` in LINQ compares contents.

```csharp
// Old: owned types (entity types with hidden keys)
modelBuilder.Entity<Customer>().OwnsOne(c => c.ShippingAddress, b => b.ToJson());
modelBuilder.Entity<Blog>().OwnsMany(b => b.Posts, b => b.ToJson());
// New (EF10)
modelBuilder.Entity<Customer>(b =>
{
    b.ComplexProperty(c => c.ShippingAddress);                 // table splitting
    b.ComplexProperty(c => c.BillingAddress, c => c.ToJson()); // JSON column, nullable if Address?
});
modelBuilder.Entity<Blog>().ComplexCollection(b => b.Posts, b => b.ToJson());
```

- **Use when**: value objects (Address, Money), document-style nested data. Prefer immutable `record`/`readonly record struct` and change values with `with` (EF still updates only the changed columns).
- **Do not use when**: the type needs identity, navigations, its own table, or shared mutable state. Use an entity type in those cases.
- **Why over owned**: owned types fail when the same instance is shared, compare by identity, and do not support ExecuteUpdate on JSON. EF11 deprecates keyless owned JSON collections.
- **Column naming changed** (breaking): see the EF10 breaking changes section.
- **Source**: whatsnew EF10 "Complex types", <https://learn.microsoft.com/en-us/ef/core/modeling/complex-types>

### 4. ExecuteUpdate on JSON columns

- **Version/status**: EF10, GA. **Requires complex-type mapping. It does not work with owned types.**
- **Providers**: SQL Server 2025/Azure SQL use `json` `.modify()`. Older SQL Server (nvarchar JSON) is supported. Npgsql 10 uses `jsonb_set`. Check other providers.

```csharp
await ctx.Blogs.ExecuteUpdateAsync(s =>
    s.SetProperty(b => b.Details.Views, b => b.Details.Views + 1));
// SQL Server 2025: UPDATE [b] SET [Details].modify('$.Views', JSON_VALUE(... RETURNING int) + 1) ...
```

- **Performance**: a set-based partial JSON update with no load/serialize round-trip.

### 5. `ExecuteUpdateAsync` accepts a regular (non-expression) lambda

- **Version/status**: EF10, GA. A **source-breaking** change for code that built `Expression<Func<SetPropertyCalls<T>,...>>` manually.
- **Providers**: all relational.

```csharp
// Old: hand-built expression trees for conditional setters (dozens of lines)
// New (EF10)
await ctx.Blogs.Where(b => b.Id == id).ExecuteUpdateAsync(s =>
{
    s.SetProperty(b => b.Views, 8);
    if (nameChanged) s.SetProperty(b => b.Name, newName);
});
```

- **Note**: the inner `SetProperty` selectors and value lambdas are still expressions and must be translatable. Only the outer setter block is a `Action`/`Func`.

### 6. Parameterized collection translation: new default

- **Version/status**: EF10, GA. Default behavior change (low-impact breaking).
- **Providers**: relational. Mode API in `Microsoft.EntityFrameworkCore.Relational`. Npgsql 10 separately changed array `Contains` to `= ANY(...)`.
- **What**: `ids.Contains(x.Id)` is now `IN (@ids1, @ids2, ...)`. The list is **padded** to reduce distinct SQL shapes (8 values become 10 params, padding repeats the last value). This gives the planner cardinality info while keeping plan-cache reuse.
- **Modes** (`ParameterTranslationMode`): `MultipleParameters` (EF10 default), `Constant` (pre-EF8), `Parameter` (single JSON array/OPENJSON, EF8-9 default).

```csharp
// Global
options.UseSqlServer(cs, o => o.UseParameterizedCollectionMode(ParameterTranslationMode.Parameter));
// Per query
ctx.Blogs.Where(b => EF.Constant(ids).Contains(b.Id));          // inline constants
ctx.Blogs.Where(b => EF.Parameter(ids).Contains(b.Id));         // single JSON parameter
ctx.Blogs.Where(b => EF.MultipleParameters(ids).Contains(b.Id)); // EF10 default
```

- **When to override**: very large lists (SQL Server's ~2100 parameter limit applies to multiple-parameter mode; prefer `Parameter`), or apps tuned for OPENJSON plans. Use `Constant` for a small, low-cardinality set of known values.
- **Obsolete**: EF9 `TranslateParameterizedCollectionsToConstants()`/`...ToParameters()` are `[Obsolete]` in EF10. Use `UseParameterizedCollectionMode`.
- **EF9 caveat still applies**: `EF.Constant`/`EF.Parameter` throw inside `EF.CompileQuery`.
- **Source**: whatsnew EF10; breaking-changes EF10; API docs `ParameterTranslationMode`.

### 7. Security: inlined constants redacted from logs

- **Version/status**: EF10, GA, on by default.
- **What**: values that EF inlines into SQL (for example `EF.Constant(...)`) are logged as `?` unless `EnableSensitiveDataLogging()` is set. The executed SQL is unchanged.
- **Impact**: reduces PII leakage into logs. Custom `IRelationalCommandDiagnosticsLogger` implementations must take the new `logCommandText` parameter (breaking).
- **Guidance**: never enable `EnableSensitiveDataLogging` in production.

### 8. Security: analyzer warns on string concatenation in raw SQL APIs

- **Version/status**: EF10, GA.
- **What**: warns on `FromSqlRaw("..." + x)` (and other "Raw" APIs).

```csharp
// Flagged
ctx.Users.FromSqlRaw("SELECT * FROM Users WHERE Name = '" + name + "'");
// Correct: parameterized via FormattableString
ctx.Users.FromSql($"SELECT * FROM Users WHERE Name = {name}");
```

- **Suppress only** for trusted or sanitized identifiers (for example a column name from an allowlist).
- The analyzer's diagnostic ID was not verified.

### 9. SQL Server: custom/named default constraints

- **Version/status**: EF10, GA. SQL Server only.

```csharp
modelBuilder.Entity<Post>().Property(p => p.CreatedDate)
    .HasDefaultValueSql("GETDATE()", "DF_Post_CreatedDate"); // explicit name
modelBuilder.UseNamedDefaultConstraints();                    // EF names all default constraints
```

- **Caveat**: with existing migrations, enabling `UseNamedDefaultConstraints` makes the next migration **rename every default constraint**.
- **Use when**: deterministic constraint names are needed for schema compare, DBA scripts, or dropping defaults reliably.

### 10. SQL Server 2025 / Azure SQL: vector type and `VECTOR_DISTANCE`

- **Version/status**: EF10, GA (EF-side). Requires **SQL Server 2025+ or Azure SQL**. Type: `Microsoft.Data.SqlTypes.SqlVector<T>` (from Microsoft.Data.SqlClient 6.1+).

```csharp
public class Blog
{
    public int Id { get; set; }
    [Column(TypeName = "vector(1536)")]
    public SqlVector<float> Embedding { get; set; }
}
// Insert
blog.Embedding = new SqlVector<float>(await generator.GenerateVectorAsync(text));
// Exact kNN search (scans all rows, no index)
var top = await ctx.Blogs
    .OrderBy(b => EF.Functions.VectorDistance("cosine", b.Embedding, queryVector))
    .Take(3).ToListAsync();
```

- **Metrics**: `cosine`, `euclidean`, `dot`. `VectorDistance` is always exact and never uses a vector index.
- **Migration**: remove the old `EFCore.SqlServer.VectorSearch` community package.
- **EF11**: approximate search via `VectorSearch()` + `HasVectorIndex` (experimental), and vectors are no longer loaded by default.
- **Source**: <https://learn.microsoft.com/en-us/ef/core/providers/sql-server/vector-search>

### 11. SQL Server 2025 / Azure SQL: native `json` type

- **Version/status**: EF10, GA.
- **When used**: automatically when configured with `UseAzureSql(...)` **or** `UseCompatibilityLevel(170)`+. Applies to primitive collections, complex/owned `ToJson()`. Queries use `JSON_VALUE(... RETURNING type)`.
- **Upgrade impact**: the first migration after upgrading **ALTERs existing nvarchar(max) JSON columns to `json`**. Opt out with `UseCompatibilityLevel(160)` or `.HasColumnType("nvarchar(max)")`.
- **Limitation**: SQL Server does not support DISTINCT over JSON arrays, so such queries fail.
- **Default compat**: `UseSqlServer` defaulted to 150 in EF10. **EF11 changes the default to 160**, so `json` is still not used by default on-prem unless you set 170.
- **Performance**: the native json type is more efficient than text storage (per Microsoft).

### 12. Azure Cosmos DB: full-text search, hybrid search, vector search GA

- **Version/status**: EF10, GA. Cosmos for NoSQL only.
- **Full-text**: `EnableFullTextSearch(lang?)` + `HasIndex(...).IsFullTextIndex()`. Functions: `EF.Functions.FullTextContains/ContainsAll/ContainsAny/FullTextScore`. `FullTextScore` is only allowed inside `OrderBy`. The default language is en-US, and `HasDefaultFullTextLanguage` sets a container default.
- **Hybrid**: `EF.Functions.Rrf(FullTextScore(...), VectorDistance(...))`, with optional `weights:`.
- **Vector search**: moved out of experimental (from EF9). APIs renamed to `IsVectorProperty`/`IsVectorIndex`. Container creation is supported for vectors on owned references, not owned collections.

```csharp
modelBuilder.Entity<Blog>(b =>
{
    b.Property(x => x.Contents).EnableFullTextSearch();
    b.HasIndex(x => x.Contents).IsFullTextIndex();
});
var hybrid = await ctx.Blogs.OrderBy(x => EF.Functions.Rrf(
        EF.Functions.FullTextScore(x.Contents, "database"),
        EF.Functions.VectorDistance(x.Vector, queryVector)))
    .Take(10).ToListAsync();
```

- **Other Cosmos EF10 changes**: missing values for newly added required properties materialize as the default instead of throwing (eases model evolution). Queries use the ExecutionStrategy (retries).
- **Source**: <https://learn.microsoft.com/en-us/ef/core/providers/cosmos/full-text-search>

### 13. Split query ordering consistency

- **Version/status**: EF10, GA (bug fix, no API).
- **What**: `AsSplitQuery()` + `OrderBy` + `Take` previously omitted the key in the subquery ORDER BY of the follow-up queries, which could correlate the wrong rows. EF10 orders consistently (`ORDER BY Name, Id`).
- **Guidance**: still always add a deterministic ORDER BY with a unique key when paging. Split queries are not consistent across concurrent writes; EF11 now throws when it detects this.

### 14. Other EF10 query and perf items

- Simplified parameter names: `@__city_0` becomes `@city` (breaking for SQL snapshot tests; expect a one-time plan recompile spike).
- New translations: `DateOnly.ToDateTime`, `DateOnly.DayNumber` (SQL Server, SQLite), `DatePart.Microsecond/Nanosecond`, COALESCE becomes ISNULL on SQL Server, decimal MAX/MIN/ORDER BY on SQLite.
- Optimizations: consecutive LIMITs, `ICollection<T>.Count`, MIN/MAX over DISTINCT. Many `DefaultIfEmpty` bug fixes. AsyncLocal changes improve lazy-loading perf.
- Migrations no longer all run inside a single transaction (reverts the EF9 behavior).
- SQLite: AUTOINCREMENT can be disabled, and works with value converters.
